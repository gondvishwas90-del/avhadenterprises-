# Workflow Overview

For every task, follow this sequence. Never skip a phase unless explicitly instructed.

1. Discovery
2. Research
3. Strategy
4. Information Architecture
5. Wireframing
6. Visual Design
7. Design System
8. Responsive Design
9. Interaction & Motion
10. Accessibility Review
11. Performance Optimization
12. Development Handoff
13. Quality Assurance
14. Final Delivery

# Phase 1 — Discovery

Before creating any design:

* Understand the business goals.
* Identify the target audience.
* Define project objectives.
* Understand user pain points.
* Clarify project scope.
* List required pages and features.
* Identify technical constraints.
* Ask questions if critical information is missing.

Deliverable:

* Project understanding summary

# Phase 2 — Research

Research similar products and industry standards.

Analyze:

* Competitors
* Industry trends
* UX patterns
* Conversion strategies
* Modern UI trends
* Best practices

Gather inspiration from:

* Awwwards
* CSS Design Awards
* Behance
* Dribbble

Use inspiration to create original work, never direct copies.

Deliverable:

* Design direction
* Inspiration summary

# Phase 3 — Strategy

Define:

* User journey
* Navigation
* Content hierarchy
* Primary CTA
* Secondary CTA
* Trust-building elements
* Conversion goals

Deliverable:

* UX strategy

# Phase 4 — Information Architecture

Organize content into logical sections.

Determine:

* Navigation structure
* Page hierarchy
* Section order
* Content grouping

Prioritize clarity and usability.

Deliverable:

* Site structure

# Phase 5 — Wireframing

Create low-fidelity layouts before visual design.

Focus on:

* Structure
* Content placement
* User flow
* Functional layout

Avoid visual styling at this stage.

Deliverable:

* Wireframes

# Phase 6 — Visual Design

Transform wireframes into premium interfaces.

Apply:

* Typography hierarchy
* Color system
* Layout grids
* Premium spacing
* Strong visual hierarchy
* Brand consistency

Design every section intentionally.

Deliverable:

* High-fidelity UI

# Phase 7 — Design System

Create reusable components.

Include:

* Buttons
* Inputs
* Cards
* Navigation
* Icons
* Typography
* Color tokens
* Spacing tokens
* Components
* States

Maintain consistency throughout the project.

Deliverable:

* Design system

# Phase 8 — Responsive Design

Optimize every screen for:

* Mobile
* Tablet
* Laptop
* Desktop
* Ultra-wide screens

Never scale desktop layouts directly.

Design responsively from the start.

Deliverable:

* Responsive layouts

# Phase 9 — Interaction & Motion

Add meaningful motion only where it improves the user experience.

Examples:

* Hover states
* Page transitions
* Scroll animations
* Loading states
* Button interactions
* Section reveals

Animations should feel smooth, subtle, and purposeful.

Deliverable:

* Interaction specifications

# Phase 10 — Accessibility Review

Verify:

* Color contrast
* Keyboard navigation
* Focus indicators
* Semantic structure
* Readability
* Touch target sizes
* Screen reader compatibility

Target WCAG compliance.

Deliverable:

* Accessibility checklist

# Phase 11 — Performance Optimization

Review:

* Image optimization
* Font loading
* Layout efficiency
* Responsive images
* Lazy loading
* Animation performance
* Core Web Vitals

Design with performance in mind.

Deliverable:

* Performance recommendations

# Phase 12 — Development Handoff

Prepare developer-ready assets.

Include:

* Component specifications
* Design tokens
* Typography scale
* Color palette
* Spacing values
* Interaction notes
* Responsive behavior
* Asset references

Ensure implementation is straightforward.

Deliverable:

* Developer handoff documentation

# Phase 13 — Quality Assurance

Before finalizing any design, verify:

* Pixel-perfect alignment
* Visual consistency
* Responsive behavior
* Accessibility
* Brand consistency
* Functional completeness
* Content accuracy
* Conversion optimization
* Originality
* Performance readiness

Resolve all issues before delivery.

Deliverable:

* QA report

# Phase 14 — Final Delivery

Provide:

* Final design
* Responsive views
* Component library
* Design tokens
* Developer notes
* Implementation guidance
* Suggested future improvements

The final output must be production-ready.

# Workflow Rules

Always:

* Think strategically before designing.
* Justify design decisions.
* Prioritize UX over decoration.
* Maintain consistency.
* Follow the design system.
* Optimize for conversions.
* Design mobile-first.
* Build reusable components.
* Keep interfaces clean and intuitive.
* Document important decisions.

Never:

* Skip research.
* Copy existing designs.
* Ignore accessibility.
* Overuse animations.
* Introduce inconsistent spacing.
* Sacrifice usability for aesthetics.
* Deliver incomplete work.
* Leave design decisions unexplained.

# Definition of Done

A project is complete only when:

* Business goals are addressed.
* User experience is intuitive.
* Visual design feels premium.
* Design system is consistent.
* Responsive layouts are finalized.
* Accessibility requirements are met.
* Performance considerations are addressed.
* Developer handoff is complete.
* Quality assurance checks pass.
* The design meets the standards of a world-class digital product suitable for award-winning recognition.
